# 项目含金量与方向评估 SOP（定稿版 v2）

> 文档性质：稳定的方法论 / 宪法层。它与项目态 handoff、阶段计划和实验结果分离维护：项目结论可以变化，本文原则不随单个项目结果而变化。
>
> 适用求职坐标：AI Infra / 推理 serving / KV cache 团队。本文所有“岗位语言”均以此为锚。
>
> 权威关系：本文约束项目选择、能力信号、证据、主张与叙事的方法；[PROJECT_PLAN.md](PROJECT_PLAN.md) 将这些原则落实为本项目的具体 Gate、STOP 与实验合同；[STATUS.md](../../STATUS.md) 始终记录实际完成状态。若项目 handoff 或计划在**方法论层**与本文冲突，应先修订项目文档，不能借项目态降低本文标准；实际运行事实不得被方法论文件覆盖。

相对 v1，本版的中心从“选题防否决”迁移到“能力信号生成”。新颖性、官方 issue、个人先验和自建 benchmark 都只是加分或证据；一票否决权属于下面的五道闸门。

## 1. 中心句与记忆公式

> 好项目不是找到一个没人做过的问题，而是在与目标岗位相关的真实系统里，拥有一条关键执行路径，对多个合理方案做出可解释的取舍，用“向上到目标函数、向下到下一层因果”的证据完成闭环，并对并发、失败、资源生命周期和结论边界负责。

```text
项目含金量 = 岗位边际价值 × 真实路径所有权 × 判断密度 × 证据强度 × 运行时完整性 × 主张诚实度
```

前五项要做大；第六项不加分，而是给其余各项的结论扩张设上限。任一项为零，项目归零。

## 2. 五道硬闸门

五道闸门是连乘关系。任一项不过，不应靠“多做功能”补救，而应缩小、换题或合法 `STOP`。

### 闸门零：岗位边际价值

先问：**它消除了面试官对我哪一个关键能力的不确定性？**

- 不重复已有信号。已经证明过的对象存储数据面、后端工程、监控或 CRUD 平台，不应再作为旗舰项目的主要能力证明。
- 当前需要新增证明的是：读懂真实推理 runtime、改动 KV 生命周期路径、测量 TTFT/goodput、处理异步状态与资源回收，以及把存储先验迁移到推理并判断哪些会失效。
- 因而，一个抽象意义上很好的存储项目，也可能不是当前简历的最优项目。

### 闸门一：真实目标函数

任何项目必须写满下面四行：

```text
最终优化对象是什么？（岗位语言）
中间代理指标是什么？
代理指标经由什么因果链影响最终目标？
这条链在什么条件下断裂？
```

可作为最终目标的岗位语言包括：resumed-TTFT、TPOT/ITL、goodput、SLO 达标率、单位资源服务能力、失败恢复时间、错误率与资源泄漏率。

命中率、显存占用和传输带宽默认只是诊断量，不能充当成功判据。若使用它们，必须提供其通向最终目标的因果链与失效条件。

### 闸门二：真实执行路径所有权

项目必须实际改变至少一项结果：

- 调度决策；
- KV block 生命周期；
- retain / offload / recompute 的实际执行；
- fallback 路径；
- 异步 completion 的接纳或拒绝；
- cleanup 与资源归属；
- 请求可运行状态；
- 数据的实际传输、恢复或重算路径。

只加日志、dashboard、配置层、prompt wrapper 或独立模拟器，不构成旗舰项目本体。

底座原则是 **adopt，而非 build**：领养现成真实引擎，底座只薄到足以暴露要改的那条路径。不要从零复造 serving 引擎或 KV 系统。

### 闸门三：判断密度

至少存在两个真正合理的候选方案，而不是预先定答案再补论证。文档必须保留：

```text
候选方案 A / B / C
各自解决了什么、破坏了什么
实验如何区分它们
为什么剪掉其中两个
什么新证据会让我翻案
```

最后一项是判断密度是否真实的标志。深度是“一条窄因果链上，可独立防守的决策数量”，不是代码层次、功能数量或问题稀有度。

### 闸门四：一层向下的证据、运行时完整性与主张边界

每个端到端数字都要能向下拆解为阶段分解与路径真值。例如：

```text
resume TTFT = decision delay + queue wait + H2D restore
            + re-admission + prefill + first-token
```

必要时继续下钻到 kernel、transport 或 scheduler。性能结论还应包含合理 baseline、控制变量、A/B 或消融、稳态区间、噪声或置信区间与可复现 manifest。

KV 生命周期问题还必须回答：并发、取消、超时、重复请求、部分失败、stale completion、cleanup 归属，以及 fallback 是否改变语义。

每条结论显式标注只在哪一层成立，不能把局部机制证据包装成生产经济结论。

## 3. 主张阶梯：控制结论扩张，而非回避硬件

要控制的不是“是否做硬件实验”，而是结论可以扩张到哪一层。

| 层级 | 含义 | 当前预算与要求 |
|---|---|---|
| C1：机制与正确性 | 例如 stale completion 污染新 epoch、接口不能区分 retry、cancel 后 restore 泄漏 | 单 GPU、CPU mock 或受控 fixture 也可裁决；优先级最高 |
| C2：局部因果性能 | 固定机器/模型/负载下，例如 restore queue wait 占 resumed TTFT 的 40% | 允许受环境限制，但必须明确环境和控制变量 |
| C3：归一化 regime | 用 restore/recompute 比、cache pressure、resume probability、concurrency 等描述在哪类负载有效 | 可以做受限外推，但仍须说明边界 |
| C4：生产经济 | 例如“H100 集群节省 12%”“RDMA 一定值得” | 没有对应硬件、真实流量或独立证据时禁止主张 |

当前项目预算应稳定做到 C1、C2，并争取有限 C3；不应声称 C4。

## 4. 证据分级与旗舰最低线

| 等级 | 证据 | 能支持什么 |
|---|---|---|
| E0 | demo、日志、一次跑通 | 存在性，不支持机制或性能结论 |
| E1 | unit / contract test | 局部行为与不变量 |
| E2 | 强制路径与 trace | 真实路径经过了目标接缝 |
| E3 | baseline、控制、消融、可复现实验 | 受限的性能或因果结论 |
| E4 | 并发、取消、失败注入、长跑、资源清理 | runtime 生命周期与失败语义 |
| E5 | 外部 review、upstream issue/PR、独立复现 | 外部可检验性；是加分，不是立项许可 |

旗舰项目最低要有 E3，并配合 E4 或 E5；KV 生命周期方向优先补 E4。一个完整证据包至少包括：源码改动、设计选择、不变量、路径 trace、控制实验、故障实验、可复现数字和有边界的结论。

比起没有失败语义的“8% 提升”，一个可重放的 stale-restore 测试或上游修复更能证明 runtime 工程能力。

## 5. 两环结构：学习脚手架与旗舰工程分离

### 环一：学习脚手架

环一只用于建立直觉，必须 time-boxed。其输出是对同一系统、同一条路径的理解；若它另起炉灶或变成独立模拟器，便会造成 scope creep。

### 环二：旗舰工程

环二遵循：

```text
adopt → narrow → own → judge
```

即：采用真实引擎，只拥有一个当前处理不好的执行路径，在窄路径上形成选择与证据闭环。DecisionTrace、invariant 和 action forcing 应在第一天进入设计。成功不等于打败 upstream 默认策略，而是能够回答：坐标是什么、路径真值是什么、生命周期合同是什么。

不要走“build → reproduce → innovate”的路线：它通常消耗在底座复刻上，既不增加路径所有权，也无法形成可追问的判断。

## 6. 面试叙事的固定骨架

按以下顺序组织，而不是按功能列表组织：

1. **经验**：已有能力和当前缺口是什么；
2. **先验**：从存储或既有系统带来了哪些假设；
3. **问题**：真实 runtime 中哪条路径、何种成本或失败语义没有被妥善处理；
4. **实验与数字**：候选 A/B 的控制实验、路径拆解与故障验证显示了什么；
5. **先验裁决**：哪些先验迁移成功，哪些失效，以及原因。

叙事规则：

- 用可审查的动词，不把 agent、upstream 或环境能力写成个人实现；
- claim surface 等于面试防守面，主张越大，需要准备的追问与证据越多；
- 最终指标使用岗位语言，而不是只报命中率、字节或阈值；
- 任何 `ROADMAP`、`SOURCE_VERIFIED`、`IMPLEMENTED_UNVALIDATED`、`EXPERIMENTALLY_VALIDATED` 都必须明确区分。

## 7. 四类固定攻击与应对

每个候选项目都应主动接受四类攻击：

1. **范围攻击**：这是否已经变成 router、eviction、存储引擎或 kernel 项目？
2. **价值攻击**：它是否已经被解决，或是否对目标岗位没有边际价值？
3. **替代攻击**：为什么不是更简单的 Y？为什么你的复杂度值得？
4. **追问攻击**：面试官沿数据路径、生命周期、实验公平性与失败语义连续追问时，能否落到证据？

答辩依赖证据三角：岗位证据、系统路径证据、负载/实验事实。没有三角中的至少两边（其中一边最好可外部核验），就不把结论写成项目价值。

## 8. 立项、扩 scope 与重开方向的纪律

### 8.1 立项前

- 做 evidence triangle：岗位、系统与 workload 证据至少命中两类，且至少一类可外部核验；官方 issue 只是证据或加分，不是项目许可。
- 做 Fermi gate：instrument 是否能获得、接入成本、样本量、故障注入成本是否在预算内。不可测、不可复现的方向不应立项。

### 8.2 执行中

- scope creep 默认拒绝；新功能必须重新通过五道闸门，并说明它是否比更简单方案多解决当前真实问题。
- 被拒绝的方向只有在“先前拒绝理由为何已失效”有新证据时才能重开。
- 负结果、losing workload 与 `STOP` 和正结果同等重要；它们是判断质量的一部分，不是失败后应隐藏的内容。
- 工具是仪器和研究助手，不是“自动施工队”。如果只能说“agent 自动跑了”，就不构成个人可防守能力；必须能解释设计、证据和失败边界。

### 8.3 Handoff 与复核

handoff 记录当前结论状态，不替代证明历史；应保留被拒绝项及理由。恢复工作或进入面试前，重新核验关键源码版本、环境、实验 artifact 和 claim state，不能把旧结论当作当前事实。

### 8.4 智能工具纪律

- 文献、官方 issue、代码搜索与 agent 可以帮助发现候选、定位路径和生成实验脚手架；它们不能替代对固定版本源码、实验设计与原始结果的理解。
- 任何“自动跑出”的结果，只有在本人能够解释输入、控制变量、路径真值、失败模式和主张边界后，才可以进入证据包。
- 不因工具降低基础标准：每项结论仍需能回到真实路径、可复现实验或明确的源码事实；不能用生成的文字填补缺失的运行时证据。
- 若工具产物无法经人工复核、重新运行或映射到五道闸门，只能作为探索记录，不进入项目主张或面试叙事。

## 9. 自检清单

在立项、扩 scope、准备简历或复盘时逐项回答：

- 它新增证明了目标岗位的哪项能力？
- 最终目标、代理指标、因果链和断裂条件是否完整？
- 是否拥有真实执行路径，而非围绕 upstream 加了一层配置？
- 候选 A/B/C、剪枝依据与翻案条件是否被记录？
- 每个端到端数字能否向下拆到路径阶段与真值？
- 并发、取消、超时、重复、部分失败、stale completion 与 cleanup 是否有明确语义？
- 结论是 C1、C2、C3 还是 C4？证据等级是否足够？
- 是否能在 45 分钟追问中展示代码、测试、raw trace、manifest 与失败条件？

## 10. 最终锚点

> 在真实推理引擎里，把 KV cache 从一个模糊的性能对象，变成一个有明确生命周期、执行路径真值、失败语义和可测成本边界的运行时资源——底座越薄越好，路径越窄越好，判断和证据全部压在那一条窄路径上往深里挖。
